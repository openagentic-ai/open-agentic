# batch

## 何时使用
- 用户说"把每个 X 都..."、"批量"、"对所有文件..."、"遍历并..."
- 需要并行独立操作（各操作间无依赖）
- 操作步骤明确、可模板化
- **不**用于：有严格顺序依赖的串行任务、需要人工判断每一步的任务

## 操作步骤

### 1. 确认范围和操作
在动手之前，先向用户确认：
```
目标：<N 个文件 / 目录 / 条目>
操作：<每一步做什么>
策略：并行 (N 个同时) / 串行 (逐个)
```

### 2. 并行执行（默认）
对无依赖的独立操作，**必须并行执行**以节省时间：

```
# 读文件 → 全并行
read_file: file1.py
read_file: file2.py
read_file: file3.py
# 三个同时发起

# 运行命令 → 全并行（各命令互不依赖）
run_command: pytest tests/test_a.py
run_command: pytest tests/test_b.py
run_command: pytest tests/test_c.py
```

### 3. 收集结果，汇总报告
所有操作完成后，汇总为统一报告：

```markdown
## Batch: <操作描述>

### 成功 (N/N)
- file1.py — <结果摘要>
- file2.py — <结果摘要>

### 失败 (N)
- file3.py — <错误信息>
  - 建议：<怎么处理>

### 统计
- 成功 N / 总数 N
- 耗时：~Xs
```

## 注意事项

### 必须做
- ✅ 确认范围后**先打印计划**再执行
- ✅ 并行操作**逐个验证成功/失败**
- ✅ 部分失败不阻断整体，记录失败项并在报告中标出
- ✅ 写文件前确认（遵守项目的 write_file 确认策略）

### 不做的事
- ❌ 不看文件就盲目操作
- ❌ 对相互依赖的操作并行执行（如"改 A.py 后立刻 test A.py"）
- ❌ 操作前不确认（批量操作影响面大，误操作代价高）
- ❌ 超大型批处理（>20 个目标）→ 建议用户拆小批次

### 安全约束
- 批量写文件 → 每个覆盖操作服从 `/permissions` 策略
- 批量 `run_command` → 每个命令服从命令前缀白/黑名单
- 批量删除文件 → 每个删除操作服从 delete 策略
- 遇到 `sudo` / `doas` 等 → 每个单独确认
