## 本地离线体验

已有本地依赖即可构建和运行，本次没有下载安装或连接外部网络：

```bash
npm --prefix ui run build
PYTHONPATH=src .venv/bin/python scripts/run_merchant_demo.py
```

打开 `http://127.0.0.1:8766/merchants`。数据保存在 `data/merchant-demo/`，后端仅监听本机地址；不调用模型、不访问生产数据库、不执行真实付款。

1. 商家注册，开通店铺并发布服务。可以先填入“本地示例”目录进行导入，再手动发布草稿。
2. 在工作台分享店铺链接，或生成并下载二维码。手机扫码必须能访问填写的站点地址，`127.0.0.1` 只对应访问设备自身；本机预览不等于手机或公网部署验收。
3. 客户使用独立账号，在公开店铺申请预约，或进入 `/agent-commerce` 查询服务、准备报价，再到 `/quotes/:id` 明确确认。当前页面使用本地工具模式，不假装已启用自然语言模型。
4. 商家在工作台接单，客户在 `/orders` 查看结果。展开“账单与售后”，可以确认模拟支付、申请退款和提交售后问题；商家回复，客户确认解决后关闭工单。
5. 商家可把已接单的订单加入本地示例投递队列，在“商家系统投递记录”执行或重试。对方收到订单不等于完成履约，履约仍由商家确认。
6. 在 `/connections` 创建限定权限的 Agent 授权令牌、查看审计和撤销授权。令牌只显示一次，服务端仅保存其 SHA-256 摘要。
7. 在 `/operations` 记录接入、接单和售后投入，关联订单并注明已有客户、平台新增或未知来源。未知来源不计为平台新增；统计来自实际数据库记录，不生成假订单。
8. `/memories` 管理第四层流程，支持 Markdown、属性、双链、反向链接和 Obsidian 打开 URI，详见 [记忆说明](obsidian-memory.md)。

标准后端默认没有支付服务商，本地示例脚本才显式启用 `LocalPaymentProvider`。页面及账单中的所有支付金额均为模拟，不表示真实收入、扣款、转账或结算。

## 标准后端

有可用的本地 PostgreSQL 时执行：

```bash
PYTHONPATH=src .venv/bin/alembic upgrade head
PYTHONPATH=src .venv/bin/uvicorn openagentic.main:app --host 127.0.0.1 --port 8000
```

前端 `npm run dev` 的 `/api` 代理指向 `127.0.0.1:8000`。独立前端部署可配置 `VITE_API_BASE_URL`，服务器需提供 SPA 路由回退。

当前 Alembic head 为 `b27a51f0c842`。三次商业增量迁移共新增 14 张表，包括店铺、成员、服务、预约，以及授权、报价、审计、接入映射、运营记录、收费、模拟支付退款、售后和投递记录。

平台运营身份须由部署者通过 `OPENAGENTIC_OPERATOR_IDS` 配置账号 UUID。默认用户只看自己管理的商家；不会因注册较早自动成为平台管理员。该配置提供平台视图及模拟费率编辑，不把普通用户令牌升级为运营权限。

## Agent 与商家系统契约

- `GET /api/commerce/tools`：当前授权可用的工具定义。
- `POST /api/commerce/tools/{name}`：`find_services`、`quote_service`、`get_order`。
- `GET /api/commerce/capabilities`：三个交付里程碑与当前支付模式。
- `commerce/client.py`：第三方 Agent 客户端，调用者提供已认证 HTTP 客户端；测试通过 ASGITransport 在进程内完成。
- `commerce/engine.py`：按账号装配已有 ConversationEngine，检索自己的核心、情节和 Obsidian 流程记忆；模型配置及执行须显式提供。本地验收使用替代模型返回验证完整工具循环，没有调用外部模型。
- `integrations/merchant_api.py`：通用商家契约 HTTP 适配器和明确标记的本地示例，尚未宣称接入某个具体 SaaS 厂商。调用者负责配置授权客户端，不从用户输入的 URL 自动抓取。

Agent 授权只允许查询服务、准备报价和查询自己的订单状态。Agent 令牌不能进入用户确认预约、支付或售后处理接口。服务下架、价格/名称/时长变化、报价过期均要求重新选择或确认；重复确认同一报价不会重复创建订单。

订单投递以订单 UUID 为幂等键，记录状态和尝试次数，单次超时 10 秒，人工重试最多 10 次，重复执行已完成投递直接返回原记录。HTTP 商家系统也必须遵守幂等契约。本地未启用后台轮询、自动回调状态覆盖或未经配置的外部连接。

## 验证与边界

验收覆盖真实 SQLite SQL、注册与 JWT、商家/买家越权、Agent 权限与撤销、确认要求、报价变更与过期、重复请求、状态迁移、目录重复导入、投递失败恢复、模拟费率快照、退款与售后、运营范围和记忆隔离。二维码通过 macOS Vision 原生独立解码，覆盖普通 URL、容量边界及中文地址。前端构建、静态检查、类型检查和 PostgreSQL 离线迁移 SQL 生成均通过；最终结果见 README。

尚需实际环境验证：真实地推和商家使用、手机扫码体验、真实 SaaS 厂商联调、真实支付服务商/结算/回调、运行中 PostgreSQL 迁移与并发。服务时间仍由商家人工确认，不提供自动时段锁定；商家团队邀请与成员角色管理尚未提供。旧渠道共享记忆迁移见记忆说明。

四项商业验证仍待真实证据：商家是否允许接触实际经营流程；是否带来订单或降低接单和服务成本；用户是否再次使用；减少创始人介入后效果是否继续成立。完成工程不能代替这些验证。
