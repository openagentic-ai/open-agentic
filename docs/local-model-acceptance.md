# 真实端侧模型集成验收

入口：

```bash
.venv/bin/python scripts/verify_local_agent.py --endpoint http://127.0.0.1:80/v1
```

需要正在运行、支持工具调用的 OpenAI-compatible 模型服务，以及开发和 Codemode 依赖：

```bash
.venv/bin/python -m pip install -e '.[dev,codemode]'
```

这个入口不使用模拟模型、不替换应用函数，不由 pytest 自动触发。它会发出实际推理请求，通过伪终端操作真正的 CLI，随后运行实际 SDK 和 CLI RPC 子进程。扩展的自定义模型提供方也真实请求同一个模型服务。

默认创建独立临时目录；`--output-dir <新目录>` 可指定证据目录。记忆、会话、provider 和权限配置都放在该目录。文件写入确认只允许临时工作区内的目标，shell 和删除工具在验收配置中禁用。个人记忆及已有 provider 配置不作为测试输入。

## 验收内容

1. CLI 启动、模型实际回复问候。
2. 模型调用 `read_file`，读取提示词中没有提供的随机校验码。
3. 先读后用 `edit_file` 精确修改，确认后核对真实文件内容。
4. 用户拒绝修改后，核对工具拒绝结果及文件保持原样。
5. 退出 CLI、重新启动并恢复同一会话，让模型从历史找回校验码。
6. 切换到读取文件以前的节点，验证当前上下文隔离且原分支仍保留。
7. SDK 实际推理过程中发送纠偏和后续任务，核对最终回复及消息顺序。
8. CLI RPC 实际让模型调用 Codemode，用 JavaScript 读取并计算文件数据。
9. RPC 写入触发权限拒绝，核对目标文件未创建。
10. RPC 正常关闭并退出。
11. 显式加载 Python 扩展，触发会话生命周期和扩展命令。
12. 模型通过自定义提供方真实推理，调用自定义工具计算文件 SHA256。
13. 扩展拦截模型的写入请求，确认不会到达写入确认及文件创建阶段。

## 证据

`live-summary.json` 汇总模型、端点、耗时、每项结果和各阶段退出码。工作区还保留：

- `terminal.log`、`terminal-resume.log`：真实终端字节流，包含终端控制序列。
- `sessions/cli.sqlite3`：实际 CLI 会话树。
- `sdk-transcript.json`：SDK 实际消息及工具调用。
- `rpc-wire.jsonl`、`rpc-stderr.log`：RPC 实际协议和诊断输出。
- `extension-transcript.json`、`extension-results.json`：扩展工具与拦截结果。
- 原始输入文件和修改后的文件，供独立核对。

任一阶段进程失败或验收项失败，入口返回非零退出码；不会用成功的单元测试覆盖真实推理的失败。推理耗时受模型、缓存和硬件影响，JSON 中记录的是本次实际耗时。

## 已发现的集成问题

首次实机扩展测试发现，测试扩展把已解析的目标路径与未解析的根路径直接比较，macOS 的 `/var`、`/private/var` 别名导致写入拦截失效。失败文件及原始结果保留；修正测试扩展的根路径规范化后，使用别名输入再次验收。运行时文档中的路径保护示例也已改为双方使用 `Path.resolve()` 后判断包含关系。

实机启动还遇到 LiteLLM 从 GitHub 获取价格表时握手超时，并回退本地备份的警告。可用已有变量 `LITELLM_LOCAL_MODEL_COST_MAP=True` 避免这项元数据请求；模型推理地址与这个价格表地址是两条独立链路。

## 2026-10-15 实测记录

在 `http://127.0.0.1:80/v1` 的实际 `Qwen3.8-27B-MLX-4bit` 上完成验收。首轮 12/13 通过，扩展测试规则修正后，重新执行完整入口得到 **13/13 通过**，三个阶段进程退出码均为 0，总耗时 274.65 秒。

本次重复验收中：问候 4.42 秒、读取文件 26.49 秒、确认修改 18.30 秒、恢复历史问答 8.50 秒、SDK 纠偏及后续任务 34.73 秒、RPC Codemode 计算 81.36 秒。功能链路通过，较复杂任务的端到端延迟仍然偏高；这些数字是单次实测，不代表稳定性能上限。
